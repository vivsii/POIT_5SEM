1.
Тезис «PL/SQL – процедурное расширение SQL»: PL/SQL является языком программирования, разработанным компанией Oracle, который дополняет SQL возможностями процедурного программирования. SQL сам по себе не является процедурным языком и не поддерживает такие конструкции, как циклы, условные операторы или переменные. PL/SQL расширяет возможности SQL, добавляя управление потоком, блоки, циклы, условия и возможность обработки исключений. Это позволяет разработчикам писать более сложные и логически структурированные программы для работы с базой данных.

2.
Чувствителен ли к регистру язык PL/SQL?
PL/SQL не чувствителен к регистру символов. Например, команды BEGIN, begin и BeGin будут восприняты одинаково. Однако, когда дело касается строковых значений и переменных в SQL запросах, регистр может иметь значение.

3.
Что такое анонимный блок? Как выглядит простейший анонимный блок PL/SQL? Почему он называется анонимным. 
Анонимный блок в PL/SQL — это блок кода, который не имеет имени и не сохраняется в базе данных для последующего использования, как, например, процедуры или функции. Он называется анонимным, потому что не имеет идентификатора. Простейший анонимный блок выглядит так:
BEGIN
   NULL;
END;

4.
Что необходимо предпринять, чтобы вывод процедуры dbms_output.put_line отображался в SQL*Plus или SQL Developer? 
Чтобы увидеть вывод от команды dbms_output.put_line, необходимо включить отображение вывода с помощью команды:
SET SERVEROUTPUT ON;
В Oracle SQL Developer: Включить опцию "DBMS Output" в настройках или через вкладку DBMS Output в интерфейсе.

5.
Из каких секций состоит программа на языке PL/SQL? Объясните их назначение. Какие из них обязательные? Программа на PL/SQL состоит из трех секций:

Объявительная секция (DECLARE): здесь объявляются переменные, константы, курсоры и другие объекты. Эта секция не обязательна.
Исполнительная секция (BEGIN ... END): в этой секции выполняются все операторы и бизнес-логика. Это обязательная секция.
Секция обработки исключений (EXCEPTION): здесь можно указать, как программа должна обрабатывать ошибки, возникающие в исполнительной секции. Эта секция не обязательна.

6.
Что такое исключение PL/SQL?
Исключение — это событие, которое прерывает нормальный ход выполнения программы. В PL/SQL существуют предопределенные и пользовательские исключения, которые можно перехватывать и обрабатывать в секции EXCEPTION. Это помогает предотвращать ошибки и сохранять стабильность программы.

7.
Что такое вложенные блоки PL/SQL? Для чего они применяются? Как работают секции исключения во вложенных блоках? 
Вложенные блоки — это блоки PL/SQL, размещенные внутри других блоков. Они позволяют локализовать переменные и исключения, что улучшает управление сложной логикой программы. Вложенные блоки могут иметь собственную секцию EXCEPTION, и если в них происходит ошибка, то она может быть обработана локально, прежде чем управление перейдет во внешний блок.

8.
Совпадают ли типы данных базы данных Oracle и PL/SQL?
Многие типы данных в PL/SQL совпадают с типами данных в SQL, например, NUMBER, VARCHAR2, DATE. Однако есть различия, например, в PL/SQL существуют такие типы, как BINARY_INTEGER, которых нет в SQL.

9.
Какая семантика символов используется в Oracle? В Oracle используется множество специальных символов, таких как:

Символы-операторы: +, -, *, /, % (например, оператор остатка).
Символы для объединения строк: ||.
Символы для операций сравнения: =, !=, <>, <=, >=.

10.
Типы данных для хранения символьной информации в базе данных Oracle и программе на PL/SQL:
В Oracle: CHAR, VARCHAR2, CLOB, NCHAR, NVARCHAR2.
В PL/SQL: CHAR, VARCHAR2, CLOB, NCHAR, NVARCHAR2.

11.
Типы данных для хранения числовых данных в базе данных Oracle и программе на PL/SQL:
В Oracle: NUMBER, FLOAT, INTEGER, DECIMAL.
В PL/SQL: NUMBER, BINARY_FLOAT, BINARY_DOUBLE, PLS_INTEGER, NATURAL, POSITIVE.

12. 
Операции, которые использовались при выполнении работы:
Арифметические операции: +, -, *, /, MOD.
Операции сравнения: =, <>, >, <, >=, <=.
Управляющие конструкции: IF, CASE, LOOP, WHILE.

13.
Представления словаря базы данных, хранящие информацию, связанную с PL/SQL:

USER_ERRORS, DBA_ERRORS — для просмотра ошибок компиляции PL/SQL.
USER_SOURCE, DBA_SOURCE — для просмотра исходного кода объектов PL/SQL.
USER_PLSQL_OBJECT_SETTINGS — для просмотра настроек PL/SQL объектов.


14.
Как получить все параметры Oracle, связанные с PL/SQL? 
Используйте команду SHOW PARAMETER в SQL*Plus или запрос к представлению V$PARAMETER:
SHOW PARAMETER plsql;
SELECT * FROM V$PARAMETER WHERE NAME LIKE '%plsql%';
